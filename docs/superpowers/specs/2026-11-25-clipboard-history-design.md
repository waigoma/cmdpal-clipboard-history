# CmdPal Clipboard History 拡張 設計書

- 日付: 2026-11-25
- 状態: 承認済み (2026-11-25)。試作の結果を反映 (同日、10 章)
- 凡例: 【決定】= 依頼者が決めた事項、【提案】= 設計側の判断 (差し替え可)、【未検証】= 実機で未確認

## 1. 意図と理由

Raycast は子プロセス込みで作業セット約 1,070 MB (専有約 790 MB) を使う。
内訳は本体、WebView2、Node.js が大半で、履歴データ (`clipboard.db`、11 MB) の容量は主因ではない。
Raycast を終了できるように、必要な機能を PowerToys Command Palette (以下 CmdPal) の拡張として作る。
最初の機能が Clipboard History である。ほかの機能は後日、別の拡張として足す。

## 2. 目標

1. 【決定】Raycast の Clipboard History をほぼ全機能再現する (範囲は 6 章)。
2. 【決定】履歴はファイルに保存し、全件をメモリに載せない。
3. 【決定】CmdPal にインストールできるプラグインにする。
4. 【決定】Alt+V で履歴を呼び出せる (Raycast での使い方を踏襲)。
5. 【提案】軽さの合格基準: 履歴 5,000 件、操作後 5 分の待機状態で、拡張プロセスの専有メモリが 30 MB 以下 (目標 15 MB)。画像 10 枚を連続コピーした後も、5 分以内に基準内へ戻る。ワーカーは含めない。届かないときは実測値を示して依頼者に相談する。
6. 【提案】速さの合格基準: 履歴 5,000 件 (1 件平均 2 KB、うち画像 200 件) で、一覧の初回表示と検索の応答が 200 ms 以内 (拡張側の処理時間)。

## 3. 対象外

- AI 連携 (Ask Clipboard、AI Chat への送信)、スニペット保存【決定】
- Share…、リンク先の画像やタイトルの取得 (通信しない)、Universal Clipboard、クラウド同期【提案】
- Raycast の既存履歴の取り込み【提案】
- 管理者権限で動くアプリへの自動貼り付け (Windows の UIPI 制限。コピーまでに留める)
- CmdPal 停止中の記録 (起動時の補完を除く)
- 履歴の暗号化【提案】: DPAPI は同一ユーザーの他プロセスを防げず、SQLCipher は OS 付属の SQLite を使えなくする
- ストア公開、winget 公開、arm64【提案】: x64 の自分用とする

## 4. してはならないこと

- 非記録指定のある内容や、除外アプリの内容を保存すること
- 貼り付け先を取り違えること。確信が持てないときは貼らず、コピーに留める
- 外部へ通信すること (`internetClient` を宣言しない)
- 履歴の本文をログに書くこと

## 5. 制約

- Windows 11 build 26300、x64。CmdPal 0.13.13096 (PowerToys 0.102)。.NET SDK 10.0.300。
- 拡張は MSIX の `com.microsoft.commandpalette` AppExtension として発見される。プロセス外 COM サーバーであり、CmdPal が起動時に開始して保持する。
- SDK は `Microsoft.CommandPalette.Extensions` 0.12.260812002。導入済みの CmdPal で動かなければ 0.11.260520004 へ下げる。
- 開発者モードは試作のため ON (依頼者が実施)。常用版の導入後は OFF に戻せる。`makeappx` と `signtool` は NuGet (`Microsoft.Windows.SDK.BuildTools`) から使う。
- 対象フレームワークは `net10.0-windows10.0.22621.0` (26100 は CsWinRT 2.2.0 でビルドできない)。AOT のリンクには `vswhere.exe` の場所を PATH に加える。
- SQLite は OS 付属の `winsqlite3.dll` (3.53.4、FTS5 と trigram あり)。OCR は `Windows.Media.Ocr` (ja、en-US 導入済み)。QR は ZXing.Net。
- 実装は haiku、レビューは sonnet の subagent が担う【決定】。1 モジュールを小さく、単体テスト可能に保つ。
- SDK の型定義で確認済み: 一覧の区分見出し (`Section`)、追加読み込み (`HasMoreItems` / `LoadMore`)、フィルタ、詳細表示、タグ、項目ごとのキー指定。見た目と動作は試作で確かめる。
- CmdPal の自動起動が前提。README で案内する。
- 内蔵の Clipboard History と Raycast には手を加えない。Alt+V が Raycast と競合する間の解除と、Raycast の停止は依頼者が行う。

## 6. 機能

### 6.1 記録

| 種別 | 判定 | 保存するもの |
|---|---|---|
| テキスト | `CF_UNICODETEXT` | 本文 (DB) |
| リンク | 前後の空白を除いた全体が http / https の URL 1 つ | テキストと同じ |
| メール | 全体がメールアドレス 1 つ (`mailto:` 可) | テキストと同じ |
| 色 | 全体が `#RGB` `#RRGGBB` `#RRGGBBAA` `rgb()` `rgba()` `hsl()` `hsla()` | テキストと同じ |
| 画像 | `PNG` または `CF_DIBV5` / `CF_DIB` | PNG ファイル |
| ファイル | `CF_HDROP` | パスの一覧 (複数でも 1 件)。ファイル本体は保存しない |

- 判定は、ファイル、テキスト系 4 種、画像の順に優先する。Office のようにテキストと画像の両方を出すアプリはテキスト扱いとし、画像も形式の一つとして残す。
- テキストと一緒に `HTML Format` と `Rich Text Format` も保存する。【提案】保存する形式はこの表と HTML / RTF に限る。独自形式は、要求した時点で元アプリに重い生成処理をさせるため扱わない。
- 重複: 種別と主内容の SHA-256 が同じなら行を増やさず、最終コピー日時を更新する。主内容は、テキスト系が改行を LF に揃えた本文 (空白は削らない)、画像が受け取った形式の生バイト列、ファイルが順序を保った小文字のパス列とする。形式は新しいもので置き換える。名前とピン留めは残す。
- 除外 1: `ExcludeClipboardContentFromMonitorProcessing` または `Clipboard Viewer Ignore` が存在する、もしくは `CanIncludeInClipboardHistory` が 0 のときは記録しない。
- 除外 2: 除外アプリ (実行ファイル名の一覧) からのコピーは記録しない。コピー元は `GetClipboardOwner` のプロセスとし、取れないときは前面ウィンドウのプロセスを使う。照合はファイル名のみ、大文字小文字を区別しない。`ApplicationFrameHost.exe` のときは、その中で動く子ウィンドウのプロセスで照合する。どうしても分からないときは記録する【提案】。
- 除外 3: 自分が書いた内容は新しい履歴として数えない。書き込み時に独自の目印形式を付け、目印があるときは無視する。
- 上限【提案】: 1 形式 50 MB、全体 2 GB (どちらも設定可)。超えた形式は保存しない。主内容が超えたときは、その件を記録しない。全体の超過時は、ピン留めのない古いものから消す。ピン留めだけで超えるときは消さず、新規の記録も続ける。
- `OpenClipboard` が競合したときは短い間隔で最大 10 回試し、失敗したら件名を含まないエラーだけをログに残す。
- 起動時の補完: 現在のクリップボードが未記録なら 1 件拾う。続いて Windows 標準の履歴から、拡張が止まっていた間のテキストとファイルを補う (前面にないプロセスから読めることを試作で確認済み)。標準の履歴はコピー元が分からないため、除外アプリが 1 つでも設定されているときと、一時停止中は、標準の履歴からの補完をしない。動作中だった時間帯の項目は補わない (削除した項目が復活しないため)。画像は標準の履歴からは補わない (元のバイト列が得られず重複を判定できないため)。
- 一時停止: 「記録を一時停止 / 再開」のトップレベルコマンドを置く【提案】。状態は再起動後も保つ。

### 6.2 一覧と検索

```
┌ クリップボード履歴を検索…                         [すべて ▾] ┐
│ ピン留め                          │                          │
│  ★ 社内 VPN 手順 (名前付き)        │  (本文 / 画像の表示)     │
│ 今日                              │                          │
│ ▌git rebase --onto main           │  種別   テキスト         │
│  🖼 画像 1920×1080                 │  コピー元 Code.exe       │
│  ■ #3A7BD5                        │  日時   11/25 14:02      │
│ 昨日                              │  文字数 24 / 1 行        │
│  📄 report.pdf ほか 2 件           │  形式   Text, HTML       │
└ ⏎ 貼り付け   Ctrl+⏎ コピー   Ctrl+K その他 ─────────────────┘
```

- 並びは、ピン留め、今日、昨日、今週、それ以前。各区分の中は最終コピー日時の新しい順。
- 検索対象は、本文 (先頭 64 KB)、付けた名前、ファイル名、OCR の文字、QR の文字。部分一致で、空白区切りは AND。大文字小文字は ASCII の範囲で区別しない。全角英数と半角英数、長音と各種ダッシュとハイフンも区別しない (OCR が「ー」を「-」と読むため)。
- 種別フィルタは、すべて、テキスト、リンク、メール、色、画像、ファイル。フィルタへの移動は CmdPal 標準の Alt+F を使う (Raycast の Ctrl+P は拡張側から割り当てられない)。
- 一覧は 50 件ずつ DB から読み、末尾に達したら追加で読む。保持するのは表示中の分だけとし、画面を離れたら手放す。
- 画像は縮小画像のファイルパスをアイコンに、元画像のパスを詳細に渡す。読み込みは CmdPal 側が行う。
- 色はその色の見本を付ける。ファイルは、存在しなくなったものに印を付ける。
- 開いている間に新しい項目が記録されたら一覧を更新する。

### 6.3 操作

| 操作 | キー | 対象 |
|---|---|---|
| アクティブなアプリへ貼り付け (既定) | Enter | すべて |
| クリップボードへコピー | Ctrl+Enter | すべて |
| プレーンテキストとして貼り付け | Ctrl+Shift+Enter | テキスト系、ファイル (パス文字列) |
| 形式を選んで貼り付け… | なし | 複数形式を持つもの |
| 内容を編集… (保存 / 保存して貼り付け) | なし | テキスト系 |
| 名前を変更… | Ctrl+E | すべて |
| ピン留め / 解除 | Ctrl+. | すべて |
| 画像から文字をコピー | なし | 画像 |
| QR コードの内容をコピー | なし | QR を含む画像 |
| 開く / 保存場所を開く | Ctrl+O | リンク、メール、画像、ファイル |
| このアプリを記録しない | なし | コピー元が分かるもの |
| 削除 | Ctrl+X | すべて |
| 期間で削除… (5 / 15 / 30 分、1 / 24 時間) | Ctrl+Shift+X | 最終コピー日時がその期間内のもの |
| すべて削除 | なし | 確認あり |

- 主操作 (Enter) は「貼り付け」と「コピー」を設定で入れ替えられる。もう一方が Ctrl+Enter になる。
- 期間で削除とすべて削除は確認を出し、ピン留めは残す【提案】。単独の削除は確認なしで即時に行う。
- 編集の保存はその項目を上書きし、HTML / RTF は捨てる。種別は再判定する。同じ内容の項目が既にあれば 1 件にまとめる。
- キーが検索欄の標準操作 (Ctrl+X の切り取りなど) と競合して動かないときは、Ctrl+Shift+Delete のような別キーへ変える【未検証】。
- リンクは http / https だけを開く。「開く」は依頼者の明示操作なので、通信しないという制約には当たらない。

### 6.4 貼り付け

CmdPal は、拡張の処理が戻ってから画面を隠す (ソース確認済み)。そこで次の順に行う。

1. 貼り付け先を決める。拡張は `SetWinEventHook` で前面の切り替わりを受け、CmdPal (`Microsoft.CmdPal.UI`) 以外で最後に前面だったウィンドウを常に 1 つ覚えておく。ホットキーからの実行では、その時点の前面ウィンドウを貼り付け先とする。それが CmdPal 自身のときは貼らない (試作で CmdPal の設定画面に貼られた)。
2. クリップボードへ書き、その時点のシーケンス番号を控える (自分の書き込みとして無視するため)。
3. 裏で監視を始め、`Hide` を返す。
4. 10 ms 間隔、最大 800 ms で、前面が 1 の貼り付け先 (同じウィンドウ、または同じプロセスのウィンドウ) になるのを待つ。
5. 修飾キーが離れるのを待ち (最大 2 秒。試作で 1 秒では足りない例があった)、50 ms 置いてから Ctrl+V を送る。
6. 待ち切れない、別のウィンドウが前面に来た、または相手が管理者権限 (`TokenElevation`。取得を拒否されたときも該当とみなす) なら送らず、クリップボードに残す。次に画面を開いたときに、その旨を一覧の上部へ表示する【提案】。

- 貼り付けは同時に 1 つだけとし、送信後も 150 ms は次の書き込みを受け付けない。試作では連打すると、先の Ctrl+V の前に次の内容で上書きされた。
- 貼り付け後もその内容はクリップボードに残す。
- 「操作後に履歴の先頭へ移動」の設定が ON なら、貼り付けとコピーで最終コピー日時を更新する。
- 画像の書き込みでは `PNG` と `CF_DIBV5` を出す。展開はワーカーが行う。

### 6.5 連続貼り付け

- トップレベルコマンド「連続貼り付け」: 実行するたびに、最新から 1 件ずつ古い方へ貼り付ける。全形式を出す。
- トップレベルコマンド「連続貼り付けをリセット」: 最新へ戻す。
- 最後の実行から制限時間 (30 秒 / 1 分 / 3 分、既定 1 分) を過ぎるか、新しい内容がコピーされたら最新に戻る。
- 始めた時点の並び (最終コピー日時順、ピン留めの優先なし) を項目 ID の列として固定する。連続貼り付け自身は日時を更新しない。
- 「テキストの後に改行を付ける」設定 (既定 ON)。
- 割り当ては CmdPal の設定で行う。ホットキーからは画面を出さずに実行される (ソース確認済み)。
- 末尾を過ぎたら何も貼らない。途中で消された項目は飛ばす。
- 前の貼り付けが終わる前の実行は無視する。位置を進めるのは Ctrl+V を送れたときだけとする。

### 6.6 画像の文字と QR

- 画像の記録後、ワーカーが PNG への変換、縮小画像の作成、OCR、QR 読み取りを行う。結果を DB に書く。
- OCR は設定で ON / OFF (既定 ON)。言語はユーザーの言語設定に従う。日本語では文字の間に空白が入るため、和文文字に挟まれた空白を取り除いて保存する。
- OCR が終わる前に「画像から文字をコピー」を選んだときは、その場でワーカーを動かし、完了後に通知する。
- ワーカーは、画像の記録時と起動時 (未処理が残る場合) に起動する。本体はプロセスの終了を待って一覧を更新する。完了の通知は CmdPal の状態表示 (`ShowStatus`) で行う。
- 処理中の印が残った行は、次の起動時に未処理へ戻す。
- 失敗した処理は 3 回まで試し、その後は失敗として記録する。画像そのものは残す。

### 6.7 設定

| 設定 | 選択肢 | 既定【提案】 |
|---|---|---|
| 保存期間 | 1 日 / 1 週 / 1 か月 / 3 か月 / 6 か月 / 1 年 / 無期限 | 3 か月 |
| 主操作 | 貼り付け / コピー | 貼り付け |
| プレーンテキストを優先 | ON / OFF | OFF |
| 操作後に履歴の先頭へ移動 | ON / OFF | ON |
| 画像の文字認識 | ON / OFF | ON |
| 除外アプリ | 実行ファイル名を 1 行に 1 つ | 空 |
| 連続貼り付けの制限時間 | 30 秒 / 1 分 / 3 分 | 1 分 |
| 連続貼り付けで改行を付ける | ON / OFF | ON |
| 1 形式の上限 / 全体の上限 | MB | 50 / 2048 |
| 保存先 | フォルダーのパス | パッケージの LocalState |

- 設定は SDK の設定機能 (`JsonSettingsManager`) で持ち、CmdPal の設定画面に出す。除外アプリは複数行入力、保存先はパスの文字入力とする。
- 期限切れの判定は最終コピー日時で行い、ピン留めは消さない。実行は起動時と 1 時間ごと。
- 保存先の変更は次回起動から有効とし、既存の履歴は移さない。既定の保存先は拡張の削除で消えるため、説明文に明記する。
- 表示文字列は日本語とする【提案】。

### 6.8 呼び出し

トップレベルの「クリップボード履歴」ページに固定の ID を持たせる。
依頼者が CmdPal の設定でこのコマンドに Alt+V を割り当てる。拡張からホットキーは登録しない。
手順は README に書く。

## 7. 作り方の検討

| 案 | 内容 | 得失 |
|---|---|---|
| **A (採用)【決定】** | 拡張が記録と表示を担当。画像処理は短命のワーカー | 常駐 1 つ。画像処理のメモリが終了と同時に返る。CmdPal 停止中は記録できない |
| B | 記録専用の常駐と、表示だけの拡張 | 記録が途切れないが、常駐が 2 つになる |
| C | すべて拡張の 1 プロセス | 最も単純だが、画像処理後のメモリが戻りにくい |

A を選んだ理由は、軽さという目的に最も合うため。記録部分を CmdPal に依存させず、B へ移せる形にする。

## 8. 構造

```
command-palett/
├ src/ClipboardHistory.Core/        CmdPal に依存しない。テスト対象
│  ├ Capture/   受信、形式の読み取り、除外判定、種別判定
│  ├ Store/     DB、ファイル、重複、保存期間、上限
│  ├ Search/    検索と絞り込み
│  ├ Paste/     書き込み、前面待ち、キー送信
│  ├ Sequence/  連続貼り付けの状態
│  └ Worker/    PNG 変換、縮小、OCR、QR、画像の書き込み
├ src/ClipboardHistory.Extension/   COM サーバー、ページ、コマンド、設定、MSIX
├ tests/ClipboardHistory.Core.Tests/
├ scripts/                          ビルド、署名、導入、削除
└ README.md
```

- 記録は、専用の STA スレッドが持つメッセージ専用ウィンドウで `AddClipboardFormatListener` を使う。二重起動は名前付き mutex で防ぐ。
- Win32 は `LibraryImport` か CsWin32 で呼ぶ。時刻、クリップボード、前面ウィンドウ、キー送信は interface の裏に置き、テストで差し替える。
- DB は SQLite の WAL。`entries` (種別、プレビュー、本文、検索用文字列、ハッシュ、コピー元、名前、ピン留め、作成日時、最終コピー日時)、`formats` (項目、形式名、ファイル、大きさ)、`jobs` (ワーカーの待ち行列)。`user_version` で版を管理する。
- 本文以外は、内容の SHA-256 を名前にしたファイルに置く。DB を先に消し、参照のないファイルを掃除で消す。書き込みは一時名に書いてから改名する。
- 検索用文字列は、本文先頭 64 KB などを連結した複製の列とする (容量の重複は許容)。検索は `LIKE` とする。試作では 5,000 件で 10〜31 ms、50,000 件で 94〜296 ms だったため、FTS5 は使わない。
- ワーカーは同じ exe を `--worker` で起動し、`jobs` を空にして終わる。同時に動くのは 1 つだけとする。本体は画像を展開しない。`CF_DIB` は生のまま一時ファイルへ書き、ワーカーが PNG にして消す。
- NativeAOT で発行する。SQLite は `Microsoft.Data.Sqlite.Core` と winsqlite3 を第一候補とし、AOT で支障が出たら薄い P/Invoke に替える。AOT 自体が成り立たなければ、trim した通常発行に替えて 2 章の基準を測り直す。
- 例外で拡張を落とさない。COM の境界と受信スレッドの入口で捕まえ、ログに残す。

## 9. 配布

- 開発中は開発者モードで `Add-AppxPackage -Register` を使う。常用版は自己署名証明書で署名した MSIX とする。
- 開発者モードの切り替えと、証明書の `LocalMachine\TrustedPeople` への登録は、セキュリティ設定なので依頼者が行う。スクリプトは証明書の作成、署名、導入までとし、登録のコマンドは README に示す。
- パッケージ名は `waigoma.CmdPal.ClipboardHistory`、発行者は `CN=waigoma` とする【提案】。
- 秘密鍵は証明書ストアに置き、リポジトリに入れない。

## 11. 検証

- Core は単体テストを書く: 種別判定、除外、重複、保存期間、上限、検索、連続貼り付けの状態、貼り付けの待ち、ワーカーの再試行。
